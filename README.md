# Tripwire

Глобальный монитор early-warning: опрос первоисточников → четыре слоя фильтрации
(детерминированные tripwire → лексико-семантический скоринг → корреляция по театрам →
менеджер алертов) → Telegram-супергруппа с форум-топиками.

Один asyncio-процесс, SQLite WAL, без Docker/Redis/брокеров и без входящих портов
(Telegram long polling).

## Что где лежит

| Путь | Назначение |
|---|---|
| `/opt/tripwire` | код + конфиги |
| `/opt/tripwire/config/*.yaml` | источники, пороги, лексикон, геозоны, tripwire |
| `/opt/tripwire/.venv` | Python 3.12 venv |
| `/var/lib/tripwire/tripwire.db` | база (WAL), бэкапы в `backups/` |
| `/etc/tripwire/secrets.env` | токены и chat_id (0600, не в git) |
| `/etc/systemd/system/tripwire.service` | unit (enabled) |

## Секреты

Скопировать шаблон и заполнить:

```bash
install -m 0600 -o tripwire -g tripwire /etc/tripwire/secrets.env.example /etc/tripwire/secrets.env
nano /etc/tripwire/secrets.env
```

Нужны: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (вида `-100…`), шесть
`TG_THREAD_*`, `TRIPWIRE_ADMINS`, `NTFY_TOPIC`. Без токена сервис работает в
dry-run: события и алерты пишутся в БД, наружу ничего не уходит.

Перевод алертов работает без ключей: Google с фолбэком на MyMemory (см. раздел
«Перевод»). Если оба провайдера недоступны, алерты уходят с оригинальными
заголовками.

Права бота в супергруппе: отправка сообщений, закрепление, редактирование; бот
должен быть админом, иначе топики и pin не работают. Privacy mode у BotFather
можно оставить включённым — команды в топиках всё равно доходят, если бот админ.

## Управление

```bash
systemctl start tripwire      # запустить
systemctl stop tripwire       # остановить
systemctl restart tripwire    # перезапуск после правки secrets.env
systemctl status tripwire     # состояние + RSS
journalctl -u tripwire -f     # логи
kill -HUP $(systemctl show -p MainPID --value tripwire)   # hot-reload YAML
```

Проверка конфигов и источников без запуска сервиса:

```bash
cd /opt/tripwire
.venv/bin/python -m tripwire --list-sources
.venv/bin/python -m tripwire --once --only usgs_sig_hour,gdacs_rss
```

Разовая проверка идёт в ту же БД, поэтому не дублирует уже увиденное.

## База

```bash
sqlite3 /var/lib/tripwire/tripwire.db ".tables"
sqlite3 /var/lib/tripwire/tripwire.db \
  "select source_id,last_ok,last_items,consecutive_failures,last_error
     from source_health order by consecutive_failures desc limit 20;"
sqlite3 /var/lib/tripwire/tripwire.db \
  "select id,theater,level,score,created_at from alerts order by id desc limit 20;"
```

Ежедневный бэкап — `backups/tripwire-YYYYMMDD.db.gz`, хранится 14 копий; раз в
неделю VACUUM. Ручной бэкап:

```bash
sqlite3 /var/lib/tripwire/tripwire.db ".backup '/root/tripwire-$(date +%F).db'"
```

## Команды в Telegram

Команды принимаются только в настроенном чате от user_id из `TRIPWIRE_ADMINS`.
Ответ приходит в тот же топик.

| Команда | Действие |
|---|---|
| `/status` | театры, счета, уровни, PPI, рынки, EWS-авиация, здоровье источников |
| `/why <alert_id\|tripwire_id>` | разбор: правила, вклад каждого источника, множители |
| `/ack [alert_id]` | подтвердить CRITICAL и остановить повторы |
| `/mute <theater> <часы>` | заглушить WARNING театра (CRITICAL не глушится) |
| `/digest` | собрать дайджест сейчас в `📊 Digest & Status` |
| `/sources [theater]` | `last_ok`, ошибки, items по источникам |
| `/test <tripwire_id>` | синтетическое событие через изолированный пайплайн в `🧪 Test` |
| `/reload` | перечитать YAML с валидацией (при ошибке остаётся старый конфиг) |
| `/threshold <theater> <level> <value>` | временный порог (по умолчанию 24 ч, пишется в `config_journal`) |

Алиасы театров: `eu_ru`, `israel`, `gulf`, `mena`, `pandemic`, `nature` — либо русские
названия. После `/reload` новые токены не подхватываются: для `secrets.env`
нужен `systemctl restart tripwire`.

## Перевод

Текст алерта переводится на русский без API-ключей: сначала Google (keyless-
эндпоинт), при ошибке — MyMemory. Нужен только исходящий HTTPS. Если оба
провайдера недоступны, в сообщение попадает оригинал. Переводятся динамическая
строка события и заголовки источников; заголовок уровня, «Важно»,
команды и служебные поля уже русские.

Настройки — секция `translate` в `config/config.yaml`: `providers: [google,
mymemory]` (порядок и фолбэк), `target_lang: RU`, `timeout_s: 3`,
`max_chars: 1200` на одно сообщение, `skip_langs: [ru, uk, be]`. Эндпоинты
можно переопределить через `google_url` и `mymemory_url`. У MyMemory дневная
квота 5 000 знаков; `mymemory_email` (необязательно) поднимает её до 50 000.

Результаты кэшируются в таблице `translations` по хэшу исходного текста и
провайдеру, записи старше 180 дней удаляются. Запросов примерно один на алерт
(все строки батчем); кэш и счётчики видны в `/status` строкой
«Перевод: google/mymemory …». Кириллица распознаётся и не переводится.

Google-эндпоинт неофициальный и может временно ограничивать запросы — на этот
случай настроен фолбэк на MyMemory. Полностью отключить перевод без правки
YAML можно переменной окружения `TRIPWIRE_TRANSLATE=0` (в тестах включена
всегда).

## Уровни и подтверждение

Уровень — это сила сигнала, а не вероятность события. Пороги (`WATCH 3.0`,
`WARNING 8.0`, `CRITICAL 16.0`) заданы в `config/thresholds.yaml`; оценка не
откалибрована, и алерт говорит об этом прямо:
`счёт 20.0 (порог 16) · подтверждение: официальный источник (tier 0) · оценка
не откалибрована`.

CRITICAL от tripwire требует подтверждения: официальный источник (tier ≤1),
официальное событие в том же кластере или два независимых издателя. Одиночная
перепечатка tier-2 остаётся WARNING (`Не подтверждено независимо`), даже если
правило объявлено CRITICAL. Исключение — гражданские правила с
`confirm: immediate_civil` (сирены, цунами, извержения): официальный локальный
сигнал сам является подтверждением.

Независимость считается по издателю (`origin_domain`), а не по хосту ленты:
две статьи Google News от разных изданий — два источника, две копии одного
издания — один; Telegram-каналы различаются по `source_id`.

Множители (индикаторы рынка, PPI, ночь, соседние театры) ускоряют сигнал, но не
могут сами поднять театр до CRITICAL: если базовый счёт без множителей ниже
порога, итог ограничен WARNING. Бонус за соседний театр считается только по
`related_theaters` в `config/geofences.yaml` (`ISRAEL↔GULF`, `EU_RU↔MENA` и
т. п.), а не по любому театру с ненулевым уровнем.

Турция вынесена в отдельный театр `MENA` (Ближний Восток): новости о Турции
больше не попадают в `EU_RU`, а переброска сил в Турцию маршрутизируется в
`MENA`.

В алерте публикуются полная дата и время UTC, сырой счёт и порог, основание
подтверждения, время публикации и получения каждого источника, оригинальный
заголовок рядом с переводом, а для неподтверждённых сигналов — блок
«Не установлено» (чего не хватает для уверенности).

### BLUF в тексте алерта

После заголовка сразу идут горизонт (`ТАКТИЧЕСКИЙ` / `СТРАТЕГИЧЕСКИЙ`), одна
строка сути, действие по уровню и театру, обязательная оговорка «это не
распоряжение органов гражданской обороны», условие опровержения и следующий
tripwire. Действия задаются в `alerts.guidance` (с переопределениями для
`NATURE`, `PANDEMIC`, `MARKETS`) и `alerts.disclaimer` в
`config/config.yaml`; `refute` и `next_tripwire` — в правиле
`config/tripwires.yaml`. Для корреляционных алертов условие опровержения —
счёт театра ниже WATCH с удержанием 6 ч, а строка «Следующий tripwire»
печатается только если правило её задаёт.

## Доставка алертов и дайджест

Оранжевые (WARNING) алерты театра `NATURE` не отправляются в Telegram, но
продолжают учитываться в счёте театра и корреляции. Список задаётся в
`alerts.suppress_warning_theaters` в `config/config.yaml`; CRITICAL театра
`NATURE` доставляется как обычно.

Автоповторы «нет /ack» отключены глобально: `alerts.critical_repeat_minutes: []`
означает одно сообщение на CRITICAL. Чтобы вернуть повторы, укажите список
минут, например `[10, 30]`; театры из `alerts.suppress_repeats_theaters`
(сейчас `NATURE`) останутся без них в любом случае.

В дайджесте отдельные события с баллом ниже `digest.min_event_score`
(по умолчанию 1.0) не показываются в WATCH.
Счёт театра и алерты при этом не меняются.

Заголовки-публикации (очерки, ретроспективы, «как X изменил Y», юбилейные
материалы) отбрасываются на уровне лексикона — список `feature_headlines` в
`config/lexicon.yaml`. Фильтр применяется к заголовку при любом tier источника,
но tripwire и доменные правила его обходят, поэтому реальная чрезвычайная
сводка не потеряется.

Научные публикации (исследования, обзоры, мета-анализы, препринты, координационные
анонсы вроде «collaborate to develop a standardized score», «vaccine research»)
тоже не попадают в алерты и счёт театра — список `research_headlines` там же.
Например, статистические релизы UKHSA с префиксом `Research:` больше не поднимают
`Здоровье`. Правило также действует при любом tier и уступает только tripwire.

Алерт WARNING/CRITICAL требует, чтобы хотя бы одно событие кластера имело
score ≥ 1.0 (`alerts.min_cluster_score`); tripwire это правило обходит. Иначе
высокий счёт театра «прицеплял» к алерту случайную бытовую новость. Кластеризация
тоже ужесточена: двух общих слов в заголовках недостаточно, если пересечение
не доминирует в обоих заголовках.

Переброска сил («США перебрасывают на Ближний Восток комплексы Patriot»,
«US deploys Patriot system in Israel», «carrier strike group to Middle East»)
считается отдельным доменным сигналом: заголовок должен содержать военный объект
(войска, силы, ЗРК/Patriot/THAAD, авианосец, ударная группа, бомбардировщики)
и глагол движения; гражданские «deploy experts» и полицейские развёртывания
не срабатывают. План или условие («may deploy», «планирует перебросить») сигнал
не даёт. Считаются и прибытия техники: военно-транспортные самолёты, «transport
planes land in Israel». Событие относится к театру назначения, а не к домашнему театру ленты:
новость «США → Ближний Восток» из Interfax (EU_RU) уходит в `GULF`, потому что
актор вне региона. Бонус `domain.force_projection.points` (8 до множителей
trust/geo) позволяет такому событию пройти порог доказательности даже при geo
0.3, но одного сообщения для WARNING недостаточно — нужна корреляция.

Пустые разделы в дайджест не выводятся: если за сутки нет событий WATCH,
строка «WATCH за сутки» не появляется; «Театры» и «Индикаторы» пропускаются,
когда данных нет. В алерте вместо «Почему важно» печатается «Важно».

Для извержений действует отдельное правило: очередной выпуск VAAC по тому же
кластеру не создаёт новое сообщение, пока код цвета и высота пепла не выросли
относительно уже известных событий. В этом случае редактируется существующая
карточка без уведомления; новый CRITICAL приходит только при повышении кода
(`green → yellow → orange → red`) или высоты пепла.

## Рынки

Источник `tradingview` раз в 10 минут снимает Brent, WTI, золото, серебро, VIX,
USD/RUB, USD/ILS, газ и DXY; сэмплы лежат в `market_samples`. События рынка
никогда не алертят и не входят в счёт театров — они питают индикатор
`market_shock` (`NORMAL`/`ANOMALY`):

- Brent: +7% за 24 ч или +4% за час;
- золото: +3% за 24 ч;
- VIX: +30% за 24 ч или значение выше 35;
- USD/RUB и USD/ILS: +5% за 24 ч (рост USD/XXX означает ослабление местной
  валюты; укрепление рубля/шекеля шоком не считается).

Падение золота или серебра на 3% за 24 ч считается шоком только вместе с ростом
VIX не менее 20% за те же сутки: снижение металла само по себе часто коррекция,
а металл плюс всплеск волатильности — уход от риска. В триггере это видно:
`Gold -3.3%/24h (VIX +33.6%)`. В дайджесте и `/status` печатаются все
рассчитанные суточные движения:
`Рынки ANOMALY (Brent +2.3%, золото -3.3%, серебро -6.2%, VIX +33.6%)`.
`ANOMALY` даёт множитель ×1.25 новым событиям театров EU_RU/ISRAEL/GULF/MENA
и PANDEMIC (множитель не может сам создать CRITICAL).

Все пороги вынесены в блок `market_shock` в `config/thresholds.yaml`:
`brent_surge_pct`, `brent_spike_pct`, `gold_rally_pct`, `metal_drop_pct`,
`vix_confirm_pct` (порог подтверждения VIX для падения металлов),
`vix_spike_pct`, `vix_high`, `fx_drop_pct`. Значения по умолчанию совпадают
с перечисленными выше, менять их можно без правки кода.

## EWS: активность авиации

Индикаторы EWS ([ews.kylemcdonald.net](https://ews.kylemcdonald.net/), MIT) —
отклонение числа бизнес-джетов и военных бортов в воздухе от недельной нормы
(ADS-B heatmap, обновление раз в 30 минут). Источники `ews_jets` и
`ews_military` забирают только префикс JSON через `Range: bytes=0-8191`
(~8 КБ на запрос вместо 100–200 КБ) и пишут уровень 1–5 в `indicator_state`.
Счёт театров они не меняют; уровни видны в дайджесте и `/status`:

```
Индикаторы: PPI NORMAL · Рынки NORMAL · Джеты 3/5 (+2.7σ) · Военные 1/5 (+0.2σ)
```

При росте уровня до 4–5 приходит отдельное сообщение в DIGEST (уровень 4 —
тревога, 5 — чрезвычайная ситуация). Повтор на том же уровне не отправляется;
после снижения ниже 4 следующее повышение снова уведомляет.

## Радиация (Safecast)

Индикатор `safecast_radiation` опрашивает API Safecast раз в 30 минут
(`unit=usv`, окно = база индикатора 3 ч + 1 ч запаса) и считает уровень 1–5 по
отклонению каждого фиксированного датчика от его же медианы за 3 ч:

- 1 `NORMAL` — выбросов нет;
- 2 `ELEVATED` — один датчик выше `max(3× медианы, медиана + 0.5 мкЗв/ч)`;
- 3 `WATCH` — два таких датчика или один с показанием выше 10 мкЗв/ч;
- 4 `ALERT` — два датчика выше 10 мкЗв/ч;
- 5 `EMERGENCY` — три и более.

Записи с будущими часами (у части датчиков сбиты часы), нулевые и
неправдоподобные (выше 100 мкЗв/ч) значения отбрасываются. Уровень виден в
дайджесте и `/status` (`Радиация NORMAL (0.11 мкЗв/ч)`), на счёт театров он не
влияет. Алертов нет: Safecast — краудсорсинг, и до накопления статистики
ложных срабатываний оповещения по нему не отправляются. Пороги — блок
`radiation` в `config/thresholds.yaml`.

## Эвакуация дипломатов

Индикатор `diplo_evac` — аналог индекса пиццы Пентагона, но по эвакуациям
посольств и консульств. Раз в 15 минут он просматривает заголовки событий за
7 дней (кроме `dropped`) и считает выбросом заголовок, где дипмиссия связана с
эвакуацией, выводом персонала, предписанным выездом, приостановкой работы или
закрытием:

- 1 `NORMAL` — совпадений нет;
- 2 `ELEVATED` — хотя бы одно событие за 7 дней;
- 3 `ANOMALY` — две разные страны за 72 часа или три события за 7 дней.

Заголовки с опровержениями и слухами (`denied`, `rumor`, `дезинформация`,
`слухи`, `опроверг`), бытовыми закрытиями (`holiday`, `weekend`, `renovation`)
и отсылками только к прошлым годам не учитываются; эвакуация специалистов АЭС
или жителей без упоминания дипмиссии тоже не считается. Одинаковые события
схлопываются по кластеру. Уровень виден в дайджесте (`Дипэвакуация ELEVATED
(1 за 7д)`) и `/status`, на счёт театров и алерты не влияет — это
наблюдательный индикатор. Окна и пороги — блок `diplo_evac` в
`config/thresholds.yaml`.

## Selftest и watchdog

Полный синтетический прогон (7 семейств tripwire, изолированная временная БД —
рабочие алерты и счета не затрагиваются):

```bash
cd /opt/tripwire
.venv/bin/python -m tripwire --selftest
.venv/bin/python -m tripwire --selftest --selftest-only TW-PAN-PHEIC
```

С реальным токеном алерты и сводка уходят в топик `🧪 Test`; без токена — dry-run.
Раз в неделю тот же прогон выполняется автоматически (`selftest_interval_days`).

Внешний dead-man timer проверяет раз в час, что сервис активен и heartbeat
моложе 15 минут; иначе перезапускает `tripwire` и пишет напрямую в Telegram:

```bash
systemctl list-timers tripwire-watchdog.timer
systemctl start tripwire-watchdog.service    # ручной прогон
journalctl -u tripwire-watchdog.service -n 20
```

Внутри процесса дополнительно отслеживается деградация: >40 % источников
недоступны >30 мин или нет новых событий >60 мин → сообщение
«МОНИТОРИНГ ДЕГРАДИРОВАН» в дайджест-топик (не чаще раза в час).

## Бэктест (приёмка, point-in-time)

Реплей исторических событий через настоящий пайплайн (те же источники, правила,
скоринг, коррелятор, алерты). Каждый сценарий получает изолированную временную БД,
рабочие алерты и счета не затрагиваются; Telegram отключён (флаг `alerts.silent`),
поэтому прогон безопасен с боевым токеном.

События подаются строго в хронологическом порядке, а часы пайплайна переводятся
на метку каждого события (`tripwire.util.set_clock`): затухание коррелятора,
окна дедупликации и кластеризации, cooldown алертов, новизна и правило
гистерезиса считаются по историческому времени, а не по «сейчас». Сценарий
содержит только публикации, известные на тот момент, поэтому движок не видит
будущее.

```bash
cd /opt/tripwire
.venv/bin/python -m tripwire --backtest
.venv/bin/python -m tripwire --backtest-only 2022-02-24-invasion,2023-10-07-hamas
.venv/bin/python -m tripwire --backtest --backtest-dir backtest
.venv/bin/python -m tripwire --backtest --backtest-json backtest-report.json
```

Сценарии лежат в `backtest/*.yaml`:

- `id`, `name`, `expect` (WATCH/WARNING/CRITICAL), `control`, `provenance`;
- `truth_at` — момент истины (начало события); от него считаются задержка и
  упреждение. Для всех событийных сценариев обязателен;
- `max_delay_min` — допустима задержка после `truth_at`;
- `min_lead_min` — требуемое упреждение до `truth_at` (ранний сигнал);
- `observation_min` — окно наблюдения контроля для нормировки ложных тревог
  на 30 дней (по умолчанию 30 дней для однодневных контролей);
- `indicators` — изменения состояния индикаторов (`market_shock`, `ppi`) в
  исторические моменты, а не текущие;
- `stages` — этапы составного сценария: `expect`/`max_delay_min` для эскалации
  или `max_level` для деэскалации (проверяются только новые карточки в окне).

Итог печатается как `Point-in-time бэктест: N/N`, метрики обнаружения, ложных
тревог и этапов; код возврата 1 при провале. Считаются:

- обнаружение и первый сигнал — момент достижения ожидаемого уровня и
  упреждение/задержка относительно `truth_at`;
- пропуски (`misses`) и near-miss (на один уровень ниже ожидания);
- ложные тревоги контролей (≥WARNING) и их число на 30 дней наблюдения;
- прохождение этапов составного сценария, включая деэскалацию.

`--backtest-json` выгружает сценарии, шаги и метрики для накопления корпуса.
Brier score и диаграммы калибровки по горизонтам отложены: для них нужен
размеченный корпус прогнозов, которого пока нет.

При ошибке печатается пошаговый дамп: время, источник, заголовок, действие и
достигнутый уровень.

Калибровка, внесённая по результатам бэктеста:

- `TW-EU-INVASION` — решение о «специальной военной операции»/полномасштабном
  вторжении только из `kremlin_events`, `kremlin_acts`, `mod_russia_tg` (tier ≤1),
  с исключением учений, сценариев и годовщин;
- `TW-RU-NUCLEAR-USE` — только фактические формулировки (удар/применение), все
  «risk of / could / may / warn / doctrine» уходят в negate;
- лексика: признание независимости ДНР/ЛНР — S3, санкционный пакет, применение
  ВС за рубежом и миротворческая миссия — S2.

Тихий 30-дневный период проверяется проспективно на боевой БД: `alerts` за
последние 30 дней должны дать 0 CRITICAL и ≤5 WARNING. Расход ресурсов —
`systemctl show tripwire -p MemoryCurrent`, `du -sh /opt/tripwire/data`,
`vnstat`/счётчики интерфейса за месяц.

## Диагностика

- Нет сообщений: проверить `journalctl -u tripwire | grep dry-run` — значит не
  заполнен `secrets.env`; затем проверить `alerts` в БД и `last_error` источников.
- Watchdog: `WatchdogSec=300`, heartbeat каждые 30 с. Если процесс завис, systemd
  перезапустит его; внешний `tripwire-watchdog.timer` дополнительно проверяет
  heartbeat раз в час и сообщает в Telegram.
- Рост RSS выше 120 МБ: снять `MemoryCurrent`, проверить число событий в кластерах
  и размер WAL; `sqlite3 … "pragma wal_checkpoint(truncate);"`.
- Источник отдаёт 0: `--once --only <id>` и `source_health.last_items/last_error`.
  Для Cloudflare/JS-сайтов используются RSS-мосты Google News с `when:2d`.

## Границы

Целевые показатели: ≤1–2 ложных CRITICAL в год, ≤3–5 WARNING в неделю,
RSS ≤120 МБ, диск ≤1 ГБ (включая 2 года БД), трафик ≤1.5 ГБ/мес.
Приёмка — point-in-time бэктест по событиям 24.02.2022, 21.02.2022,
07.10.2023, 13–14.04.2024, 14.09.2019, 30.01.2020, 11.03.2020, 15.01.2022,
06.02.2023, этапам 2026 года и контроль ложных срабатываний (учения, ротации,
выборная риторика, ложная эвакуация, временное закрытие аэропорта ≤ WATCH).
