# Разметка M2: пошагово для человека

Инструкция для независимого человеческого прохода. Цель — Cohen kappa между
вашими метками и слепым агентским проходом по одному раунду. Kappa измеряет
словарь, а не данные: расхождение означает, что правило сформулировано
неоднозначно, а не что кто-то ошибся. Порог — 0.7, минимум 5 пар, 95% CI
считается bootstrap 1000 с seed 42.

Схема — `../schema.md` (v2.1). Протокол раундов — `README.md`. Этот файл —
практический порядок действий.

## Шаг 1. Откройте рабочий лист

`backtest/labels/m2/<дата>/worksheet.user.md`. В нём 25 блоков по времени
якоря. В каждом: заголовок, театр, страна, время якоря, конец окна, источники
с tier и ссылками, иногда текст новости. В конце блока — строка ответа:

```
ОТВЕТ> case_type=; почему=; ссылка=
```

## Шаг 2. Разберите один эпизод

1. **Прочитайте якорь.** Что именно система увидела первой: удар, заявление,
   переброску, протест, публикацию? Откройте ссылку, если заголовка мало.
2. **Определите субъект.** Актор + цель/локация этого эпизода. Не «любое
   событие страны». Удар по Виннице и удар по Харькову — разные эпизоды.
   Предупреждение страны X о действиях Y и само действие Y — тоже разные:
   субъект исхода Y, это исход его собственного эпизода.
3. **Проверьте окно.** 168 часов после `first_seen`. Конец окна указан в
   блоке. Все окна этого раунда закрыты, обновлять метку потом не нужно.
   События позже конца окна не считаются, даже если они важны.
4. **Найдите, что стало с той же ситуацией.** Поиск по субъекту и датам
   окна. Достаточно одного надёжного источника, чтобы понять, было ли
   материальное развитие. Не нашли — это тоже результат.
5. **Примите решение по порядку из шага 3** и запишите ответ.

Ориентир по времени: 3–5 минут на эпизод, около двух часов на 25.

## Шаг 3. Порядок решения

Проверяйте строго сверху вниз, первое подходящее правило и есть ответ.

1. Субъект и театр расходятся → **`out_of_scope`**.
2. Эпизод вообще не про безопасность — быт, культура, спорт, внутренняя
   социальная политика → **`out_of_scope`**.
3. Материальное событие той же ситуации уже было на якоре, нового после него
   нет → **`detection`**.
4. После якоря появилось материальное развитие той же ситуации →
   **`anticipatory`**. Приоритет выше `detection`, если событие новое.
5. Только заявления, встречи, бюджет или политика по безопасности и внешней
   политике → **`non_material`**.
6. Проверить нельзя → **`unresolved`**.

Бытовое отличается от `non_material` по предмету, а не по масштабу: заявление
министра здравоохранения о достижениях медицины — `out_of_scope`; заявление о
готовности применить силу — `non_material`.

## Шаг 4. Ловушки, на которых чаще всего расходятся

- **Фоновые серии.** Регулярные атаки/перехваты чаще раза в 72 ч — фон.
  Очередной ночной рейд той же интенсивности исходом не является. Исход серии
  — только качественная эскалация: аномальный масштаб (новый рекорд), новый
  класс целей, первый в серии эффект (жертвы, повреждение инфраструктуры).
- **Символические политические акты.** Designation, санкции, ответные
  «чёрные списки» — сигналинг без прямого операционного эффекта: severity 1,
  `non_material`, даже если оформлены официальным решением ведомства.
  `posture`/severity 2 — только при прямом операционном эффекте: закрытие
  пространства, запрет прохода, изменение правил применения силы.
- **Послеякорные реакции.** Подтверждение, опровержение, атрибуция,
  расследование, запрос комментария на уже свершившееся — не материальное
  развитие эпизода.
- **Отмена и нормализация.** Окончание события, снятие ограничений,
  возобновление штатной работы — не исход. Если материальное событие было до
  якоря, а после — только завершение, тип остаётся `detection`.
- **Церемониальные материалы.** Поздравления, награды, юбилеи ведомств,
  включая силовые, — протокол, `out_of_scope`.
- **Реализация чужой угрозы.** Субъект исхода — исполнитель. Это исход его
  собственного эпизода, а не эпизода предупредившего.
- **Процедурные публикации.** Открытые выступления, вебинары, guidance,
  годовые и месячные ретроспективы — не событие безопасности, даже если
  выпущены ВОЗ или другим tier-0 источником.

Спорная связь якоря и события — `confidence: medium`; сомнительная — `low`.
Спорный случай, который не меняет негатив на позитив, переразметки не требует.

## Шаг 5. Доказательства и tier

Шкала операционная, из `config/sources.yaml` (строка 3) — та же, что у
конвейера. Иначе confidence несравним с trust.

| tier | Что это | Примеры |
|---|---|---|
| 0 | официальный факт | документ или заявление первоисточника: gov.uk FCDO, МАГАТЭ |
| 1 | правительственная/межправительственная пресса | Совет ЕС, EEAS, SPA, UKMTO |
| 2 | агентства, официальные каналы, именованные профильные медиа | РИА, Интерфакс, Укринформ, Reuters, Al Jazeera, BBC |
| 3 | OSINT и рынки | ISW/Critical Threats, IMPACT-se, GDELT, UCDP GED |

Домен вне реестра получает tier по этой шкале, а не по репутации издания:
think-tank и NGO-исследования — tier 3, даже если это профильный мониторинг.

Confidence (пороги применяются к любому `case_type`, не только к кинетике):
`high` — tier 0/1 или ≥2 независимых origin-домена tier 2; `medium` — один
tier-2 источник; `low` — сомнение в самом событии или субъекте. Tier 3 сам по
себе `high` не даёт ни при каком числе доменов; если кроме tier 3 есть только
якорный источник, confidence не выше `medium`.

Вам tier проставлять не нужно — я выведу его из домена по таблице. От вас
нужна только ссылка, которую вы реально открыли.

Ссылка должна открываться и содержать само событие. URL поисковой выдачи
(`google.com/search`, `news.google.com/rss/articles` и подобные) доказательством
исхода не является. Якорные ссылки из `candidates.jsonl` — исключение: они
копируются как есть, включая редиректы.

## Шаг 6. Запишите ответ

В строке `ОТВЕТ>` заполните три поля через `;`:

```
ОТВЕТ> case_type=anticipatory; почему=после якоря 05.11 удар по той же базе 07.11, подтверждён Интерфаксом; ссылка=https://interfax.ru/world/1127818
```

- `case_type` — ровно одно из пяти значений шага 3.
- `почему` — одна строка по-русски: что вы увидели и почему это такой тип.
  Без секретов и персональных данных.
- `ссылка` — публичный URL статьи, которую открыли. Проверяли только якорь —
  оставьте пустым.

`unresolved` — честный ответ, а не пропуск. Пустая строка ответа означает
«эпизод не размечен», и он выпадет из пары.

Остальное я заполняю механически по схеме, не принимая решений за вас:
`outcome`, `outcome_type`, `outcome_severity` выводятся из `case_type`;
`outcome_at` — из указанной вами даты события; `observed_until` — фактическое
время вашей проверки; `label_id`, `candidate_id`, `cluster_id`, `theater` — из
шаблона; `evidence` и tier — из вашей ссылки и якоря.

## Шаг 7. Что происходит после

1. Вы говорите, что лист заполнен.
2. Я запускаю слепой агентский проход по всем 93 кандидатам раунда
   (`labels.agent.jsonl`). Агент не видит ваших ответов.
3. Я собираю `labels.jsonl` из ваших 25 ответов. Ваши `case_type` переносятся
   дословно, без правок.
4. Считаю kappa: `python -m tripwire --kappa-labels --kappa-dir <раунд>
   --kappa-json <раунд>/agreement.json`. Отчёт замораживается до любых
   исправлений.
5. Разбираем расхождения. Меняется `case_type` — новая строка с `supersedes`,
   старая не перезаписывается. Решение по спорному эпизоду ваше.
6. Остальные 68 кандидатов раунда можно добавить в корпус из агентского
   прохода — **только после** того, как kappa заморожена, иначе агентские
   строки спарятся сами с собой и завысят согласие.
7. Ставлю маркер `.labels-ready`, и воскресная автоматика заливки берёт раунд
   на VPS и пересобирает aggregate.
